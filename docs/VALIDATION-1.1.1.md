## 实际运行环境与边界

使用独立部署目录与进程环境，将 PATH 设为 Windows 系统目录。开始前通过真实子进程确认 `git --version`、`uv --version` 均找不到命令；没有卸载或改动机器现有软件。

- 官方 MinGit 2.56.0.4 x64 和 uv 0.13.7 实际下载、SHA256 校验、解压并执行；只给部署子进程增加工具路径。工具清单还包含 ARM64，但 ARM64 本次没有实机验收。
- 复现了 Windows 在刚运行 uv.exe 后短暂拒绝移动目录，加入有界重试后成功。不会强制删除目标目录。
- AstrBot 使用独立 Python 3.12.14、153 项依赖安装及 66 项 pyproject 一致性检查；官方桥接实际安装并导入通过。重复 AstrBot 请求返回同一正在运行的任务。
- NapCat 实际校验、解压，单项与总部署共享任务；首次初始化仍标记 partial，需要运行官方安装器和扫码。
- 插件本体在 PATH 不含 Git / uv 的进程里，经桌面自带 CLI 0.2.1-rc.5 以本地 TGZ 装入独立测试 profile，报告版本 1.1.1。
- 前端使用虚构工作区：新增工具准备按钮、部署选择说明与取消操作正常，未连接真实 QQ、未复用账号 / 密钥。

这不是一台从未装过开发工具的全新 Windows，也不是全部资源的无缓存下载验收：AstrBot 固定提交源码、公开 Python / 依赖缓存和 ONNX 模型文件复用了已校验的本地缓存。测试中曾遇到远端 Git 大包停滞及临时网络错误，错误被保留；源码使用缓存后继续验证环境安装。线上资源下载仍取决于用户网络，不取消 TLS / SHA256 校验。
